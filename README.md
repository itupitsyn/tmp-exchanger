# Exchanger

Обмен файлами между машинами: положил — забрал. Пути сохраняются относительно корня проекта в VS Code.

- `web/` — Next.js + Tailwind + shadcn. Файлы лежат в `web/storage/files/<относительный путь>` (или в `STORAGE_DIR`).
- `vscode-extension/` — расширение VS Code: отправка и получение файлов с путями.

## Сервер

Docker (из корня репозитория):

```sh
docker compose up -d --build   # http://<хост>:3500
```

Файлы хранятся в томе `exchanger-data` (`/data` внутри контейнера).

Локально для разработки (нужен [Bun](https://bun.sh)):

```sh
cd web
bun install
bun run dev          # http://localhost:3000, слушает все интерфейсы (доступен по LAN)
```

Авторизации нет — запускай только в доверенной сети.

## Расширение

Проще всего — со страницы сервера: внизу блок «Расширение VS Code» с кнопкой «Скачать .vsix» и командой установки в одну строку (PowerShell / bash). Сервер раздаёт самый свежий `exchanger-*.vsix` из `EXTENSION_DIR` (в Docker-образе он собирается вместе с приложением, локально берётся из `vscode-extension/`).

Собрать вручную:

```sh
cd vscode-extension
bun run package      # → exchanger-0.4.0.vsix
code --install-extension exchanger-0.4.0.vsix
```

Настройка `exchanger.serverUrl` — адрес сервера, например `http://192.168.1.133:3500`. Задавать руками не обязательно: при первом перетаскивании страница передаёт свой адрес, и расширение после подтверждения сохраняет его само.

- **Exchanger: Send** — ПКМ по файлам/папкам в Explorer, по вкладке или в редакторе. Путь берётся относительно корня workspace; несохранённые изменения тоже уходят.
- **Exchanger: Pull** — из палитры команд (кладёт в корень workspace) или ПКМ по папке (кладёт относительно неё). Перед перезаписью спрашивает.
- `exchanger.deleteAfterPull` — удалять с сервера то, что забрал.

## API

| Метод | URL | |
|---|---|---|
| GET | `/api/files` | список `{ files: [{ path, name, size, mtime }] }` |
| PUT | `/api/files?path=src/a.ts` | тело запроса — содержимое файла |
| GET | `/api/files/raw?path=src/a.ts` | скачать |
| DELETE | `/api/files?path=src/a.ts` / `?all=1` | удалить один / всё |

## Drag & drop из VS Code

VS Code при перетаскивании в браузер отдаёт только пути (`codefiles`), без содержимого. Поэтому страница передаёт пути расширению через сервер, а оно само читает файлы и загружает:

1. **Знакомство (один раз на машину/браузер).** При первом перетаскивании страница сразу открывает `vscode://local.exchanger/pair?id=…`. Расширение сообщает серверу свой `clientId` (один на машину), страница запоминает его в `localStorage`.
2. **Дальше** страница кладёт пути в `/api/relay` для этого `clientId`, все окна VS Code на машине забирают их long-poll'ом, каждое загружает только файлы из своего workspace и отчитывается в `/api/relay/result`.

Ссылку `vscode://` Chrome без клика открывает только раз за загрузку страницы, поэтому она используется только для знакомства.

## Drag & drop из браузера в VS Code

Встроенный Explorer VS Code принимает только настоящие файлы с диска, поэтому перетаскивание принимает расширение. Строка таблицы несёт тип `application/vnd.exchanger.file+json` (`{ server, files: [{ path }] }`), и бросить её можно:

- **в открытый редактор, держа Shift** — так VS Code разрешает drop в редактор; в документ ничего не вставляется, файл ложится в проект по своему пути;
- **в панель «Exchanger» в Explorer** — без Shift. Там же список файлов на сервере: клик по файлу забирает его в проект.

Принимаются только файлы с сервера из `exchanger.serverUrl`. Что пришло при перетаскивании — видно в Output → «Exchanger».

Без перетаскивания — команда **Exchanger: Pull**.
